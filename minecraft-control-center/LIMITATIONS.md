# Актуальные ограничения MCC 0.8

- Ore ALL_TIME начинается при включённом учёте MCC: Vanilla не хранит точную прежнюю историю натуральной добычи для импорта. Пропущенные/переполненные очереди и ограниченное происхождение placements явно раскрываются. Подозрительный цвет не доказывает чит и не наказывает.
- LuckPerms autocomplete использует публично объявленные Bukkit права и записи открытого holder. Некоторые плагины не объявляют все динамические права; точное имя доступно вручную. Метаданные read-only, holders свыше 500 узлов read-only; storage/API не предоставляет MCC совместную транзакцию со всеми внешними редакторами.
- События и автоматизации имеют бюджеты задач, длительности, очередей, выдачи и loaded anchors. OFF прекращает дальнейшие шаги; уже выполненные игровые действия не отменяются магически. Будущие plugin-action adapters и новый источник загрузки плагинов не входят в 0.8.
- Maximum сохраняет distances, но меняет механику ферм/AI/collisions и доступный redstone implementation; это не сохранение полной Vanilla семантики. Paper/Purpur проверки относятся к точным протестированным builds. Spigot — contract/profile tests, Folia/Vanilla/Fabric/Forge не поддерживаются Bukkit-плагином.
- Статичные SVG item models покрывают bounded block geometry; не все builtin/условные renderer варианты, NBT и skins. Карта и optional CoreProtect/Grim native проверки сохраняют свои прежние явно указанные границы.
- Снижение количества работы подтверждается отдельными проверками модулей. Абсолютная экономия всей JVM RAM и идеальная/безаварийная работа при любой нагрузке не заявляются.

## Актуальные ограничения 0.7

MCC0.7 добавляет профили `custom`, `vanilla`, `vanilla-performance`, `optimized`, интеграции LuckPerms/CoreProtect/AdvancedBan/AdvancedBanZ/GrimAC, наблюдение за добычей и штатный restart через supervisor protocol2. Точные проверки и границы выпуска: [VISUAL-AUDIT-0.7](docs/VISUAL-AUDIT-0.7.md). Актуальный asset-патч исправляет прозрачный crop головы Гаста; backend/JS/CSS и остальные JAR entries байт-в-байт совпадают с предыдущим проверенным кандидатом.

- Профили меняют небольшой проверенный allowlist существующего ядра. Только доступные public distance setters применяются сразу; остальные настройки требуют restart. Custom сохраняет текущие файлы и существующие per-world overrides. Полная эквивалентность Mojang и ускорение любой нагрузки не обещаются.
- Native проверены Paper26.3, LuckPerms5.5.71 и AdvancedBanZ4.0.1. Сборка против Spigot API, public reflection и fail-closed capabilities улучшают переносимость, но не подтверждают произвольные Bukkit forks. Vanilla/Fabric/Forge/Folia не поддерживаются этим Bukkit-плагином. Current asset scope имеет два собственных запуска и17checkpoints; исторический495 full15 остаётся отдельным доказательством исходного feature scope.
- LuckPerms: права, группы и наследование с контекстами/сроками; metadata только чтение. CoreProtect: ограниченный readonly поиск, без rollback/purge. AdvancedBan/AdvancedBanZ используют отдельный provider adapter; при включённом известном провайдере встроенное MCC enforcement блокируется, прежние истории и уже существующие native bans автоматически не переносятся. Неподдерживаемый API или несколько competing providers дают недоступность, без fallback к встроенным наказаниям. LiteBans/BanManager/LibertyBans обнаруживаются для такой блокировки, но их управление не реализовано. Native AdvancedBanZ4.0.1 проверен на реальном readonly запросе и targetless блокировке встроенных операций (HTTP503); создание/отмена provider санкций native не испытывались. Public provider API может самостоятельно удалять истёкшие записи кеша. Grim: readonly readings, без historical alerts/автонаказаний. CoreProtect/Grim имеют контрактные тесты, без native проверки конкретной версии.
- «Честная игра» считает подтверждённые сломанные ore blocks Survival за1/5/10мин. Цвет отражает темп, а не доказательство X-Ray; Fortune не умножает количество, auto-ban нет. Учёт поставленных блоков ограничен текущим запуском, TTL и caps; старые placements/поршни/изменения других плагинов могут иметь неизвестное происхождение.
- Restart требует внешнего supervisor protocol2 и normal exit0. Без него MCC показывает недоступность операции. Принудительный kill и `/reload` не используются. Managed profiles надёжно восстанавливаются до JVM через offline hook; без него late reconciliation честно сохраняет pending restart.
- Bounded caches/queues/metrics и PNG-map уменьшают отдельные расходы MCC. Whole JVM memory включает ядро и миры; достоверный отдельный объём MCC, benchmark и длительный JVM soak не подтверждены. G1 workaround устраняет конкретный документированный vendor path, а не гарантирует отсутствие любых будущих сбоев.
- Актуальная native карта проверена после полного сканирования:138FULL/2021slots/scanned2021, coherence1, нулевые pending/failures/scanFailures/Bukkit chunk loads/plugin tickets. Исторический495 full15 checkpoint показывал cached138/slots0, а completed138/2021 относится к его отдельному закрытому addon; эти scopes не подменяют друг друга. Первый обход большого реального мира может занимать значительно дольше короткого локального прогона.
- Текущие42page captures и дополнительные Ghast/LP/ABZ/restart снимки просмотрены на390/768/1280; они не заменяют formal accessibility audit или проверку всех состояний. Очень длинные world ID могут переноситься посимвольно; полное имя сохраняется. Local horizontal scroll таблиц/графа является намеренным поведением.

## Ограничения карты и движения, действующие с 0.6

## Актуальные ограничения0.6

Карта — собственная статичная изометрическая PNG-пирамида по сохранённой FULL-поверхности Anvil. Она следует подходу Dynmap с постоянными изображениями и zoom tiles, но не является полной копией его renderer: нет cave/interior views, texture packs, biome shading и произвольной камеры. Непрогружённые в игре территории не генерируются. Первый обход постепенно создаёт изображения всех сохранённых FULL-чанков; UI показывает его состояние. Позже обзор всего сохранённого мира доступен из постоянного кеша. Изменения появляются после обычного сохранения Paper и фонового обхода. Ошибки/неподдержанный codec отдельного record не загружают чанк через Bukkit.

Плагины: большой живой каталог Modrinth+подборка популярных проектов. Кнопка установки требует стабильный релиз, явно объявляющий точную текущую версию и серверную платформу; отсутствие такого релиза блокирует установку, даже если плагин может практически работать. Проекты только на Spigot/GitHub/официальном сайте сохраняют ссылки, автоматическая загрузка из этих источников не реализована. Платные JAR не скачиваются. Проверка metadata/хешей не заменяет native проверку конкретного стороннего плагина. Активация только при штатном перезапуске. Доступные интеграции0.7 перечислены выше.

Начальный admin/admin подходит только для локального входа. Для удалённого доступа нужно задать собственный пароль в профиле. Существующие пользователи при обычном обновлении сохраняются; разовая миграция конкретного локального owner выполняется отдельно после закрытой резервной копии и штатной остановки.

Ниже сохранены ограничения и отчёты предыдущих версий; описание viewport sampling0.5 больше не является runtime картой0.6.

Полный бесконечный мир не загружается в браузер или память сервера. Просмотр разрешён по любым допустимым координатам; показываются существующие полностью сформированные чанки. Индекс Anvil отражает сохранённое покрытие (не обещает наличие готового рельефа для каждого проточанка), сканирует до2048 файлов регионов и помечает обрезание; viewport до7×7 чанков. Карта — фиксированная изометрическая проекция на Canvas2D: только pan/zoom, без вращения камеры и строительства. Загрузка использует disk-only persisted FULL preflight и `generate=false`; ENTITY_TICKING plugin tickets удалены, snapshot снимается сразу в callback при TPS≥18 и максимум один за tick. Это не гарантия неизменности всех соседних proto records Paper или нулевой нагрузки. Индекс не следует трактовать как FULL count. Preflight ограничен1MiB compressed/2MiB decoded NBT; gzip/zlib/raw поддерживаются, external `.mcc` и другие compression codecs остаются недоступны с повторяемым error вместо load.

Кеш64 чанка/очередь64, максимум2 асинхронных загрузки и8 временных tickets. Снимок снимается максимум один за tick при TPS≥18, обработка/индекс работают вне основного игрового потока. Surface sampler читает до256 верхних блоков, глубокие voxel слои и leases редактора удалены. Разовый snapshot не прерывается по таймеру: бюджет1 ms мягкий и не доказывает постоянный overhead ниже1 ms. Карта показывает верхнюю поверхность и её высоту; пещеры, подземные блоки, внутренности построек и точные модели всех сложных блоков не отображаются. BuildEngine и его API удалены, старые сохранённые истории остаются в SQL архиве.

Декоративная 3D-сцена работает в браузере до30fps, приостанавливается вне экрана/в скрытой вкладке и при reduced motion. Это авторский voxel персонаж, не персональный skin игрока. Для отображения нужен WebGL; при его недоступности показано состояние fallback. Wheel inertia умеренная, не перехватывает точные trackpad-жесты, zoom, поля ввода, модальные окна и 3D/graph canvas. Эти детали не создают игровые серверные задачи.

## Совместимость и эксплуатация

- Проверенная сборка: Paper26.1.2 build74, Java25, Windows10. Linux, другие26.x, Purpur и Folia не протестированы. Folia не заявляется: dispatcher использует обычный основной Paper Scheduler.
- Временный сервер для игровых ботов использует offline-mode только на127.0.0.1. Для публичного сервера нужен online-mode=true и собственные настройки безопасности. Скрипт установки по умолчанию использует online-mode=true.
- Bind/port/Origin/cookies применяются при старте. Некоторые Minecraft параметры применяются только runtime; API `server.settings` возвращает сведения о persistence. Whitelist сохраняется нативным Minecraft API, поэтому перед его изменением MCC копирует стандартный `server.properties` в защищённый `config-backups/`. При нестандартном пути конфигурации меняйте whitelist offline.
- Сторонние JAR не загружаются и не удаляются динамически. Upload ≤16MiB даёт staging + SHA-256, а не гарантию безопасности или совместимости. Применение staged install/update и removal пока ручное при остановленном Paper.
- Онлайн backup включает SQLite и config MCC. Полный согласованный backup/restore миров, расписание backup и автоматическая retention файлов ещё не реализованы. Копию миров делайте при остановленном сервере. CRC и SHA-256 MCC архива проверяются при создании.

## Интерфейс и игровые модули

- Аватары игроков используют общий игровой образ, а не личный skin. Полный 3D skin viewer ещё не реализован. В 0.2 добавлены локальные игровые текстуры и авторская иллюстрация; отдельные модели и слои предметов упрощены.
- UI построен на React/TypeScript/Vite с собственными CSS/SVG/store и lazy pages. Tailwind/Motion/Recharts/Lucide/Zustand из исходного желаемого стека не используются: текущая версия уменьшает runtime frontend зависимостей. Это явное отклонение от списка инструментов, не изменение модели One JAR.
- 3D-карта — настоящая loaded-only область 8–32 блока по каждой оси; сложные формы отображаются кубами. Нет полного непрерывного рендера всех миров, зон или waypoint manager. Строительство ограничено4096 блоками и безопасными BlockData; жидкости, контейнеры и опасные/составные блоки отклоняются. Clipboard не переживает restart. Старый 2D endpoint сохраняет cache8 тайлов/5min.
- Inspector/инвентарь требуют онлайн-игрока. Известные offline-игроки — те, кого MCC наблюдал и сохранил; весь прежний каталог playerdata не сканируется. Права/бан можно изменить для известного UUID offline.
- Item Editor поддерживает ограниченное подмножество ItemMeta, а не все Data Components/NBT. При изменении того же Material сохраняется clone оригинального предмета; при создании нового Material только явно поддержанные поля переносятся.
- Mob Inspector работает с загруженными сущностями. Полный редактор оборудования/target/effects моба ещё не завершён. Требуется отдельно проверять возможности каждого EntityType; destructive Wither/EnderDragon требуют подтверждения.
- Шесть рабочих events имеют лимиты/паузы/очистку; расширенные арены, фазы boss, rewards, meteor impact, participant manager и пользовательский DSL ещё не реализованы.
- Автоматизация: граф DAG до32 узлов/64 соединений, четыре события (join/quit/death/interval), пять условий, десять безопасных действий, паузы суммарно до60sec. Это собственный редактор в стиле n8n; интеграции и произвольный JavaScript n8n не выполняются. Один общий узел после нескольких веток выполняется один раз. Максимум4 одновременных запуска/1 на правило, deadline90sec. Ручной запуск требует Admin/Owner и подтверждения; автоматические interval/cooldown ≥30sec. При перезапуске незавершённые запуски отмечаются отменёнными и не повторяются.
- `server.settings` (MOTD/whitelist/maxPlayers) и `/api/entities` доступны через API; UI возможности перечислены в `frontend/FRONTEND-REVIEW.md`.
- В Dashboard нет отдельных карточек RAM системы и диска, хотя эти значения есть в API. Item UI не редактирует flags/custom model data/attributes; REST поддерживает их. Маркеры карты обновляются при новом запросе тайла, отдельного live refresh пока нет.
- AI Administrator, saved locations/teleport presets и полнофункциональный Achievement Center отсутствуют. Достижения и статистика онлайн-игрока доступны в Inspector.

## История, доставка и производительность

- Chat и console имеют bounded историю текущего запуска. Audit/metrics/пользователи/настройки/правила/mutes/известные игроки сохраняются в SQLite. В SQLite нет continuous coordinate writes.
- WebSocket передаёт snapshots выбранных тем и события; универсальный field-level delta протокол и полноценный batching событий ещё не реализованы. Сессия проверяется при доставке/входящих сообщениях, после reconnect клиент запрашивает full state. Dedup action cache10min теряется при перезапуске.
- Очереди ограничены. При отказе storage после изменения игры состояние может быть уже применено; обновите его перед повтором. Подробные задачи backup/upload при прерывании HTTP проверяйте по их сохранённому списку.
- CPU в Dashboard — весь Java-процесс (нормализовано по CPU системы), не CPU MCC. A/B замеры процесса в PERFORMANCE.md приведены в процентах одного ядра. Память отдельных Java компонентов достоверно не измеряется.
- p95 snapshot относится только к снятию показателей, не ко всем операциям и задачам плагина. Проверены короткие локальные прогоны с3 WebSocket и5 idle protocol clients/1 WebSocket. Реалистичный gameplay с5–20 игроками, production-scale миры, активный многоклиентный Inspector, полноценная нагрузка/GC и длительный uptime требуют отдельного стенда. Целевые overhead/latency из ТЗ не являются гарантией.

Порядок продолжения, критерии и расположение проекта: `ROADMAP.md`.
