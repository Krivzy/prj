# Minecraft Control Center 0.11 — Один JAR

Java launcher теперь находится внутри `MinecraftControlCenter.jar`. Этот файл можно установить как обычный Bukkit-плагин или запустить им сервер для штатного перезапуска из панели без Python и отдельного launcher. [Запуск, остановка и миграция](docs/EMBEDDED-LAUNCHER.md). Новый релиз также объединяет отмену запросов карты с их timeout, исправляет синхронизацию лицензии между клиентами и проверки отключённого модуля игроков. Reader/writer FileLock defects воспроизведены и исправлены; текущая source-сборка `66d4…` прошла 413 Java, 135 Node и 32 Python теста, TypeScript/Vite/Gradle. Свежие 13 real-Java synthetic cases прошли и закрыты без force kill. Свежий native прогон прошёл: Paper 14 checks с Core migration/refresh, Purpur семь ordinary lifecycle checks; процессы закрыты. Offline deployment Main прошёл: заменены только MCC JAR и локальные Start/Stop scripts; остальные 11 222 файла совпали побайтно. Main остаётся OFF и не запускался; его Core binding обновится при следующем разрешённом пользователем boot. Прежние кандидаты `006689…` (12/13 process cases, terminal CLI stop failure) и `24d504…` сохранены как история отдельных JAR. [Релиз 0.11 и границы доказательств](docs/MCC-0.11-RELEASE.md); прежние отчёты ниже относятся к прежним версиям.

Bukkit-плагин со встроенной Minecraft-панелью: 14 основных разделов и условные вкладки интеграций, реальные данные, HTTP/REST/WebSocket и SQLite. Интерфейс использует тёмный камень, зелёные акценты, Monocraft с кириллицей и Minecraft-анимации.

В 0.10 владелец создаёт собственный пароль через персональную одноразовую ссылку из Minecraft. Чистая установка не создаёт публичных учётных данных. Мастер предлагает реальные пресеты ядра, пробный или временный полный доступ и предварительный MCC Core. [Первый запуск и ограничения](docs/ONBOARDING.md), [MCC Core](docs/MCC-CORE.md).

## Исправления 0.9

Анимированные сцены миров, цвет травы/листвы, оригинальные курсоры [Cursors Extended](https://modrinth.com/mod/minecraft-cursor), редактор наказаний с реальной историей провайдера и указанием источника, удаление/восстановление JAR через offline hook и проверка повторной установки. Обычная стрелка Cursors Extended статична; во время настоящего ожидания используется его исходная восьмикадровая анимация. [Источник, лицензия и поведение курсоров](docs/CURSORS-EXTENDED.md). Редактор показывает окно последних 1000 записей, а не полную выгрузку истории; изменения доступны Owner с подтверждением и проверкой ревизии. Уведомление о пропусках добычи можно закрыть для текущего запуска MCC. При доступном `localStorage` подтверждение сохраняется после повторного открытия браузера; при его блокировке действует только в памяти страницы. История и ошибки хранения остаются видимыми. [Релиз и статус проверок](docs/MCC-0.9-RELEASE.md), [визуальный отчёт](docs/VISUAL-AUDIT-0.9.md).

- [События](docs/EVENTS.md): 24 настраиваемых сценария, собственные ресурсы/мобы/точки/награды и ограниченные бюджеты. [Автоматизации](docs/GRAPH-API.md): несколько постоянных профилей, расширенные native триггеры/условия/действия, фоновое выполнение включённых цепочек без открытого браузера.
- Каталог предметов шире; ступени, плиты и ограды используют настоящую ограниченную геометрию моделей клиента в статичном SVG. В 0.8 был добавлен собственный пиксельный курсор; в 0.9 его заменили оригинальными изображениями Cursors Extended. [Изображения](docs/GAME-ASSETS.md).
- [12 модулей](docs/MODULES.md) прекращают соответствующую работу сервера и запросы интерфейса при OFF. [Максимальная оптимизация](docs/KERNEL-PROFILES.md) сохраняет обзор/симуляцию и явно сообщает изменения AI/ферм/redstone; неподдержанные схемы отклоняются.

## Восстановление и сборка

Нужны Git, Python 3.10+, JDK 25, Node.js 24 и npm; Gradle wrapper 9.2.1. Переменная `JAVA_HOME` должна указывать на JDK 25 с `javac`. Compile API — официальный Spigot 26.3 snapshot `20261004.024323-9`; runtime-проверки конкретной сборки перечислены в документах релиза. Для Paper/Purpur/Spigot используется общий Bukkit API и проверка наличия дополнительных функций. Folia требует другого scheduler и явно не поддерживается; Vanilla/Fabric/Forge не загружают Bukkit-плагины. Совместимость произвольных версий и форков не гарантируется.

Публичный source snapshot не содержит generated foundation JAR. На чистом checkout сначала восстановите закреплённый движок из официального Paper source; команда выполняется из корня проекта MCC и не запускает Minecraft-сервер. [Foundation build, исходный pin и ограничения](core-engine/README.md).

```powershell
python core-engine/build-engine.py --checkout core-engine/.work/paper --output generated/core-engine/MCC-Core-engine-0.2.0-26.3.jar
```

Затем соберите MCC командами ниже. Уже существующую проверенную foundation не перезаписывайте: builder отклоняет существующий output, а `verifyCoreFoundation` проверяет точный release SHA перед упаковкой.

```powershell
npm ci --prefix frontend --no-audit --no-fund
npm run test --prefix frontend
npm run build --prefix frontend
.\gradlew.bat --no-daemon -PskipFrontend=true build
```

Стандартная Gradle-сборка также выполняет frontend install/build/test. Итог: `build/libs/MinecraftControlCenter.jar` и SHA256. Один JAR содержит backend и статический frontend; отдельный Node.js production process не нужен.

История source-сборки 0.10: прошла 354 Java, 123 Node и 32 Python теста без failures/errors/skips. Свежие Paper/Purpur стенды прошли 33/31 проверки и по пять штатных запусков, затем закрыты; Core отказал до миров в четырёх negative boots. QA browser проверил Trial sidebar при 1285/903/375/320 px, временный полный доступ и Core 0.2 desktop/mobile. Main обновлён после полной закрытой копии и оставлен включённым на прежнем Paper/8080; browser показывает ожидание личной setup-ссылки из Minecraft, Root не создавал Owner. Workload performance-сравнение завершено со статусом INCOMPLETE: только три из девяти измеренных boots прошли и штатно закрыты; ресурсная остановка не позволяет сделать статистический вывод о скорости Core. [Точная область и receipts](docs/MCC-0.10-RELEASE.md), [визуальная проверка](docs/VISUAL-AUDIT-0.10.md).

История подтверждённой 0.9: source-сборка с оригинальными курсорами Cursors Extended прошла 303 теста Java, 111 тестов Node и 12 тестов Python без ошибок и пропусков; TypeScript, Vite и Gradle завершились успешно. Этот точный JAR прошёл native-проверки свежих Paper/Purpur 26.3: четыре запуска каждого ядра, затем штатное завершение. Интерфейс проверен в браузере при 1127, 953 и 390 px. Сборка установлена на Main после полной закрытой копии и штатного перезапуска; сервер оставлен включённым. Хеш JAR, фактический объём проверок и ограничения указаны в документах релиза и визуальном отчёте; предыдущие проверки сохранены как история.

Публичный снимок включает исходники, тесты, build configuration, документы, Monocraft/SIL OFL1.1 и неизменённые изображения курсоров Cursors Extended с его MIT notice и provenance. Миры, пользовательская SQLite база, runtime secrets/configuration, private backups, браузерные снимки и Minecraft-текстуры исключены. Владелец извлекает игровые изображения из своего клиента; fallback остаётся работоспособным:

```powershell
python scripts/Extract-Assets.py --client "$env:APPDATA/.minecraft/versions/26.3/26.3.jar"
```

## Установка

Поместите JAR в `plugins/` совместимого Bukkit-сервера и запустите его. При первом входе оператора OP (либо игрока с `mcc.setup`) MCC отправит ему личную кликабельную ссылку в чате. Получить новую ссылку: `/mcc setup`; из серверной консоли: `mcc setup <onlinePlayer>`. Ссылка действует 10 минут. Оставайтесь в игре до завершения настройки.

В браузере ник уже подтверждён сервером. Задайте свой пароль от 12 символов, выберите пресет и режим панели. В пробном режиме доступны обзор сервера, консоль, чат и настройки; остальные разделы заблокированы, их фоновые модули не работают. Временный полный доступ открывает функции без ключа, пока система лицензий находится в разработке. Активация настоящих ключей пока не подключена.

Новая установка использует `http://localhost:8123` — стандартный web-порт Dynmap. Если хостинг выделил другой порт для Dynmap, укажите его в `web.port`; уже настроенный порт, включая `8080`, сохраняется при обновлении. MCC и Dynmap не могут одновременно слушать один адрес и порт. [Настройка порта на хостинге](docs/HOSTING-PORT.md). Удалённый доступ требует явно заданного `web.public-origin` и настройки HTTPS по [SECURITY.md](SECURITY.md). MCC не угадывает внешний адрес по IP игрока.

Обычные обновления сохраняют действующих пользователей, базу и миры. Единственный известный старый Owner `admin` с неизменённым публичным паролем переводится на безопасную первичную настройку; остальные аккаунты не удаляются. Значение `auth.bootstrap-admin` и старый `.setup-token` больше не создают владельца. `scripts/Migrate-Local-Admin.java` оставлен только как исторический инструмент прежних версий; для 0.10 не используйте его для возврата публичного пароля. Пользовательские credentials не входят в GitHub.

Обновление требует штатной остановки Minecraft и его parent. Сначала сохраните текущую согласованную MCC/Core пару и закрытую offline-копию database/configuration/миров; дождитесь завершения обоих процессов, замените JAR и используйте выбранный запуск 0.11. Перед миграцией legacy v2 → embedded v3 старый launcher должен быть полностью закрыт. [Запуск и обновление binding](docs/EMBEDDED-LAUNCHER.md). Для отката верните прежний JAR после normal stop. Автоматический откат разовой миграции базы допустим только до последующих записей Paper и при совпадении её хеша с результатом миграции; иначе требуется отдельное восстановление с сохранением новых данных. Не используйте `/reload`.

Для Microsoft OpenJDK с известной сигнатурой G1 имеется [документированный обход двумя JVM-флагами](docs/JVM-G1-MITIGATION.md). Он сохраняет G1 и требует согласованного изменения launcher; короткая проверка запуска не заменяет длительный тест стабильности.

## Плагины и карта

Каталог использует Modrinth: поиск, сортировку популярности, подборку известных проектов, точную совместимость стабильного релиза и обязательные зависимости. Owner подтверждает план, MCC загружает и проверяет SHA512/JAR identity, атомарно сохраняет файлы в `plugins/`, затем показывает необходимость перезапуска. Это разрешённая установка стороннего Java-кода; metadata не гарантирует его качество. Проекты без подходящего релиза отображаются без активной кнопки установки. Обычные JAR, добавленные вручную, видны после запуска Paper. [Контракт каталога](docs/PLUGIN-CATALOG.md).

Карта использует постоянные изображения256×256 и zoom pyramid, как подход статичных тайлов Dynmap. Единственный ограниченный фоновый worker читает сохранённые FULL-records Anvil, без загрузки/генерации чанков через Bukkit. Первый обход рисует всю сохранённую поверхность постепенно, последующие показывают готовые изображения. Просмотр не запускает terrain rendering; живые позиции игроков обновляются отдельно. Это собственная реализация без полного набора renderer features Dynmap. [Карта и ограничения](docs/ISOMETRIC-MAP.md).

## История функций 0.7

- [Пресеты ядра](docs/KERNEL-PROFILES.md): Vanilla, Vanilla+, Optimized и свои файлы. Только доступные публичные setters работают сразу; остальные изменения честно требуют restart. Launcher выполняет offline hook перед чтением ядром файлов, чтобы управляемый пресет восстанавливался после ручных правок. Custom не меняет файлы.
- [Интеграции](docs/INTEGRATIONS.md): условные вкладки LuckPerms/управления наказаниями/CoreProtect и Grim в «Честной игре». API вызовы встроены в наш интерфейс; неподдерживаемая версия показывает причину. Включённый AdvancedBan, AdvancedBanZ, LiteBans, BanManager или LibertyBans приостанавливает исполнение наказаний MCC, включая сохранённые записи; история сохраняется и не переносится автоматически. Полноценный адаптер наказаний есть для AdvancedBan/AdvancedBanZ; остальные известные провайдеры блокируют встроенные действия и показывают недоступность API. CoreProtect — ограниченный поиск истории; rollback этой версии не добавлен.
- [Честная игра](docs/ORE-MONITOR.md): реальные успешно сломанные блоки руды в старых окнах 1/5/10 минут (в 0.8 заменены на 5/30/60 минут и всё время); Fortune не умножает счётчик. Цвет — сигнал темпа для проверки, не доказательство X-Ray и не автоматический ban. Указаны ограничения учёта установленных игроком блоков и сброса после restart.
- [Перезапуск и recovery](docs/SERVER-SUPERVISOR.md): Owner подтверждает штатный stop/save/start; Minecraft-анимация ждёт новый bootId. Без launcher кнопка объясняет отсутствие capability. После неожиданных завершений launcher делает ограниченные попытки с задержкой; crash loop останавливается для диагностики.
- [Переносимость](docs/BUKKIT-COMPATIBILITY.md) и [расход памяти](PERFORMANCE.md): ограниченные очереди/кеши, компактная история, SQL выборка до разбора JSON, меньшая частота снимков без зрителей.
