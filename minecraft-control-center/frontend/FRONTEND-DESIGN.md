# MCC — визуальный контракт интерфейса

## Первичная настройка 0.10

Первый запуск — отдельный lazy экран из четырёх шагов: подтверждённый Minecraft-профиль и личный пароль, профиль ядра, доступ к функциям и итог с предложением MCC Core. Тёмная каменная палитра, Monocraft для заголовков и зелёный акцент сохранены. Слева компактный маршрут и плоская SVG-сцена маяка; справа рабочая форма. На телефоне остаются четыре коротких индикатора, сцена скрывается. Принятая палитра берётся из semantic CSS variables, отдельной темы нет.

Одноразовая ссылка содержит непрозрачный token в URL fragment. Frontend удаляет его из адресной строки и обменивает на HttpOnly setup-cookie; GET status позволяет продолжить шаги после обновления страницы. Ник и UUID сообщает сервер. Ник не редактируется и не отправляется в complete. Пароль хранится только в React-памяти, имеет подтверждение и ошибки с aria-describedby; минимум 12 символов, после создания владельца поля очищаются. Общего admin/admin и поля для ручного setup token нет.

Профили берутся из фактического KernelProfiles DTO, выбор создаёт ограниченный по времени серверный план. «Ванильная производительность» рекомендуется только если доступна: сохраняет дистанции и активность механик; интерфейс отдельно предупреждает о tradeoffs агрессивных профилей и следующем перезапуске. В раскрывающемся блоке видны настоящие изменения файла. MCC Core предлагается только по `available` сервера, предварительная версия и необходимость штатного offline-перезапуска обозначены прямо. Предложение не обещает измеренного превосходства над Purpur.

Пробная версия открывает обзор, консоль, чат и настройки. Остальные доступные роли разделы остаются серыми с пояснением «полная версия». Поиск разделов не предлагает заблокированные страницы. Frontend дополнительно ограничивает live topics и player HTTP; окончательные проверки лицензии выполняет backend. Настройки показывают текущий режим и Owner может временно открыть всё без ключа либо вернуться к пробному режиму. Поле лицензионного ключа явно выключено, пока активация не реализована.

Motion владеет только opacity/translate оболочки текущего шага: exit 180 ms, вход 16 px, короткая реакция прогресса 200 ms. Beacon — CSS/SVG, без Canvas, rAF и кадровых React renders. Reduced-motion сохраняет шаги без перемещения и останавливает искры; скрытая вкладка останавливает декоративный loop. Native radio/button/fieldset, видимый focus, названия ошибок, loading, expired-link, already-configured, unsupported-core и повторная проверка статуса предусмотрены. Приёмка включает 320/390 px и desktop, keyboard flow, RU/EN, reload claim-cookie, одноразовую ссылку, смену trial/full и визуальный осмотр переходов; результаты браузерной проверки фиксируются отдельно от typecheck.

## Актуальный стиль и общие компоненты

Действующая тема — тёмный Minecraft Control Center: фон `#111315`, каменные панели `#1c2124` и `#252c30`, светлый текст `#eef5ef`, трава `#81e9a1` для главного действия, выбора и focus. Заголовки и ключевые показатели используют Monocraft; формы, таблицы и пояснения — Segoe UI / system-ui. Углы контролов 3–4 px, панели 5–6 px. Игровые изображения локальные; новые внешние UI-зависимости для визуальных исправлений не добавляются.

`style.css` подключает базовую структуру `feature-layout.css`, затем авторитетную тему `overworld-theme.css`. Общие правила обращаются к настоящим DOM-классам (`world-tile`, `directory-list`, `profile-options`, `module-list`, `table-scroll`), чтобы старые синие поверхности и мелкий текст не просачивались в отдельные разделы.

У карточки мира имя занимает всю первую строку, а значок измерения находится рядом с типом мира во второй. Обычные имена сохраняют читаемость; произвольно длинные имена могут переноситься. Карточки игроков, миров, действий, профилей и модулей используют одну каменную палитру; выбранное состояние обозначено зелёной поверхностью и границей.

Таблицы резервных копий, аудита и подготовленных JAR сохраняют нормальный размер текста и локальную горизонтальную прокрутку при недостатке места. Дата, статус и SHA резервной копии не распадаются на узкие вертикальные фрагменты. Каталог мобов сохраняет полные подписи: 3 столбца на узком экране и 2 при ширине не более 360 px. На мобильном экране navigation drawer использует горизонтальные строки от 44 px с подписью 14 px и отдельным местом для индикатора выбора; выход из панели доступен в drawer.

Shared modal исключает disabled, скрытые и inert controls из keyboard focus trap, сохраняет стек окон, Escape и возврат focus. Поиск плагинов с нулём результатов показывает empty state и позволяет очистить запрос. Основные контролы имеют состояния default, hover, selected, disabled, loading и видимый focus; reduced motion сохраняет статичное содержание.

## Предыдущее визуальное решение v0.3

Ниже сохранена история прежнего светлого Minecraft-верстака. Его палитра и композиция не являются действующей темой.

Пользователь выбрал новую композицию вместо интерфейса 0.2. Impeccable не применяется. Рабочие операции, 13 разделов, права и подтверждения сохранены.

## Визуальная система

Основные поверхности — Stone `#EEF1F5` и White `#FFFFFF`; текст Ink `#24313C`, тёмный HUD `#19222B`, Copper `#D8753C` и Cyan `#169DB3`. Граница `#D8DFE5`, вторичный текст `#657481`. Bahnschrift для игровых заголовков и показателей, Segoe UI для форм; внешние шрифты не нужны.

```text
┌ MCC ───── server/live ───────────── language/account ┐
├ World / Control / System ───────── players / TPS ────┤
│ ■ │  telemetry strip                               │
│ ■ │  ┌ real 3D mesh workbench ┐  ┌ tool slots ┐      │
│ ■ │  │ rig / mining / portal │  │ in game    │      │
│ ■ │  └ world / time / weather┘  └────────────┘      │
│ ■ │  server pulse ───────────── recent activity      │
│   │  resource strip                                 │
├──────────────── Создано пользователем Krivzy ────────┤
```

Вместо широкого sidebar используется rack 64px с настоящими game icons; на телефоне он горизонтальный. Группы инструментов находятся под HUD. Dashboard перестроен вокруг сцены и игрового dock, без прежних фиолетовых hero-карточек. Игроки выбираются из горизонтального roster, миры — из dimension tabs, плагины показаны строками. Длинные описания основных разделов открываются по запросу. Каталоги и инвентарь используют каменные слоты с нажатием и hover.

## Настоящая 3D-анимация

`WorkbenchScene.tsx` загружает `workbench3d.ts` отдельным lazy-модулем. В сцене отдельные meshes головы, корпуса, рук, ног, кирки, блоков и портала. Пивоты меняют походку и движения добычи, новые блоки появляются по очереди; shader портала и частицы обновляются в том же цикле. Текстуры блоков берутся из локального Minecraft manifest. PNG hero не используется.

Сцена декоративная, с оригинальным персонажем: она не выдаётся за состояние мира или skin игрока. Реальная карта/строительство находятся в отдельном MapPage.

Цикл ограничен 30fps, DPR ≤1.6. IntersectionObserver и Page Visibility останавливают цикл вне экрана/в скрытой вкладке. `prefers-reduced-motion` показывает неподвижный кадр. Пользователь может поставить сцену на паузу. Cleanup отменяет rAF, observers/listeners, освобождает geometry/materials/textures/renderer/context. Текстуры кешируются внутри сцены; React не обновляется каждый кадр.

## Взаимодействие

Умеренная инерция применяется только к крупным mouse-wheel шагам основной страницы: входной шаг ограничен 240px, движение сходится к цели без overshoot. Последние 2.5px переходят точно к цели, учитывая округление browser `scrollY` и завершая rAF. Trackpad, touch, клавиатура, поля, окна, nested scroll areas, карта и graph с `data-smooth-scroll="off"` сохраняют собственную прокрутку. Смена раздела/ввод/скрытие вкладки/reduced-motion отменяют старый цикл. IntersectionObserver открывает panels при появлении; route/modal/tab/hover/press/DnD переходы короткие.

`CatalogPicker` сохраняет полный API-каталог, локализованный поиск, категории и ограничение 60/30 карточек в DOM. Item workbench — количество, name/lore/damage/unbreakable и зачарования; inventory — main/ender, armor/offhand/hotbar, swap DnD и keyboard/mobile numeric swap.

Новая AutomationGraph коллеги интегрирована через lazy import; Admin/Owner подписываются на `automation`, per-node events передаются в `mcc-automation-event`. MapPage и AutomationGraph используют общие CSS tokens и UI API.

## Достоверность и доступность

Все метрики, журналы, игроки и игровые изменения идут через серверные API. Pending HTTP 202 опрашивается по исходному ID, один POST. Queued отличается от completed. Viewer не отправляет action; backend подтверждает полномочия. Пароль не сохраняется в browser storage; cookie HttpOnly и CSRF в памяти.

Modal сохраняет focus trap и стек, Escape закрывает верхнее окно, cancel не отправляет mutation. Поля и game-icon buttons имеют доступные названия; focus виден. Layout от 320px, RU/EN, loading/error/empty и точный footer «Создано пользователем Krivzy» присутствуют на app/login.

Финальная проверка новой композиции: 26 Node tests и 60 Edge/Playwright checks, 13 разделов RU/EN, desktop 1440px/mobile 390px, pause/offscreen/reduced-motion/reveal/wheel. Browser checks повторены на конечном JAR после исправлений карты. Provenance и пределы проверки перечислены в `FRONTEND-REVIEW.md`.
