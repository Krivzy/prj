# Безопасность MCC

## Действующие изменения0.6

Новая пустая установка получает admin/admin только при loopback bind, `allow-lan:false` и пустом `public-origin`. Начальный пароль отмечен в SQLite и не допускается для удалённого TCP source, LAN/proxy-конфигурации, HTTP API и WebSocket. Переименование сохраняет ограничение; смена на пароль≥12символов снимает его. Существующая база при обычном обновлении не сбрасывается. Самоудаление и удаление последнего Owner запрещены; удаление отзывает все сессии и сохраняет историю. Удалённая либо отозванная сессия не может создавать новых пользователей.

Каталог получает metadata и JAR только по HTTPS от `api.modrinth.com`/`cdn.modrinth.com`, без произвольных URL и redirect. Проверяются точные game_versions+Paper/Bukkit/Spigot metadata стабильного релиза, SHA512 источника, SHA256 результата, безопасный plugin.yml/paper-plugin.yml, уникальность plugin identity и обязательные зависимости. JAR сохраняются атомарно без перезаписи существующих файлов; при ошибке откатываются только новые файлы этой операции. Actor/TTL/single-use план и повторная проверка прав перед публикацией защищают установку. Совместимость metadata не гарантирует качество кода стороннего плагина: загрузка произвольного Java plugin — доверенное действие Owner. Автоматическое включение, hot reload и сторонние API-интеграции отсутствуют.

PNG-карта требует активную сессию, не имеет публичного tile endpoint, отдаёт `Cache-Control: private`. Сохранённые Anvil/NBT читаются отдельным ограниченным worker; не выполняются загрузка/генерация чанков, сохранение мира или plugin tickets. Позиции игроков получают только с авторизацией. Размеры входов, кешей и тайлов ограничены.

Предыдущие разделы ниже содержат базовые защиты и историю; новые контракты0.6 описаны в [API.md](API.md).

> Обновление 0.2: игровой интерфейс, анимированные изображения, admin bootstrap и смена данных, наказания и 3D-строительство описаны в [docs/V2-CHANGES.md](docs/V2-CHANGES.md). Пункты ниже о первоначальном scope/проверках 0.1 сохраняются как история; для этих новых функций актуальны отчёты v2.

## Границы доступа

По умолчанию HTTP и Minecraft в локальном тестовом скрипте слушают loopback. Bind, внешняя публикация и firewall автоматически не меняются. LAN разрешается только явным config параметром и разрешённым Origin. Host validation защищает от DNS rebinding. Для внешнего HTTPS-прокси включите Secure cookies.

Пароли: Argon2id v19, 64 MiB, 3 прохода, parallelism 1, случайная соль 16 bytes и hash 32 bytes. Одновременно выполняются не более двух KDF. В SQLite хранятся только хеши. Начальный admin/admin создаётся однократно только на loopback, без allow-lan и public-origin. Его нужно изменить в профиле; после смены старый вход не действует. При выключенном bootstrap первое создание Owner требует одноразовый случайный токен и loopback source.

Сессии: случайные 256-bit ID, 8 часов, HttpOnly, SameSite=Strict, path=/, максимум 512 сессий. Сессии хранятся в памяти и теряются при перезапуске. CSRF обязателен для authenticated POST/DELETE. Browser Origin проверяется; для CLI без Origin действуют session+CSRF. WebSocket требует сессию и разрешённый Origin, повторно проверяет сессию при сообщениях/доставке.

## Роли

| Роль | Доступ |
|---|---|
| Viewer | Dashboard, показатели, игроки/Inspector, миры без seed, каталоги, события, настройки для чтения, карта |
| Moderator | Viewer + чат/инвентарь для чтения/audit, kick/ban/unban/mute/unmute/heal/feed/message/freeze/broadcast |
| Admin | Большинство игровых действий, автоматизации, профиль и модули, список плагинов, чтение консоли |
| Owner | Все поддержанные действия, выполнение разрешённых консольных команд, OP/DeOP/IP bans, пользователи, MCC backups и staging JAR |

Опасные типизированные действия требуют `confirmed:true`; UI показывает подтверждение. Это подтверждение администратора панели для игровых действий. Изменения реальной инфраструктуры из чата требуют отдельно соблюдать инструкции пользователя.

## Ограничения ресурсов и команд

- HTTP JSON ≤64 KiB, заголовки ≤16 KiB, nesting depth ≤24; duplicate JSON keys отклоняются. Загрузка JAR ≤16 MiB только для Owner и только в staging.
- HTTP 300 запросов/min/IP; auth 8/min/IP; действия 120/min/user. 4 HTTP worker, queue128.
- Main-thread dispatch queue256; SQLite queue1024; event encoder queue256; WebSocket16 соединений, максимум4/user, queue32/клиент, ограниченные сообщения и idle timeout. Медленный клиент отключается и должен выполнить полный resync.
- Команды: точный whitelist корневых Minecraft labels. Namespaced commands, многострочные команды, execute/function/data/schedule, stop/reload, опасные команды модификации блоков/ядра/permissions и команды ОС блокируются.
- Значения валидируются до изменения. Minecraft API вызывается на основном Paper-потоке. HTTP/SQL/JSON/сжатие/файлы работают вне игровых тиков.
- Карта только для просмотра: существующие чанки читаются ограниченно с `generate=false`; новые территории не генерируются. Строительные endpoints удалены с ответом410, BuildEngine отсутствует. Spawn/event limits и TPS Guard не отключают модерацию.

## Хранение и аудит

Каталог данных, база, setup token, staging и backups получают ограниченные owner/SYSTEM ACL на Windows или 0700/0600 на POSIX. Эти права подходят серверу, запущенному под одним сервисным аккаунтом. Смена аккаунта службы требует явной настройки владельца/ACL.

Audit записывает actor/action/result/params, исключая поля password/token/secret/API key. Не вводите секреты в игровые сообщения, имена предметов или консоль: свободный текст может попасть в игровые логи, чат и backup. Фильтр redaction не является системой DLP.

JAR upload не является проверкой доверия к коду: staging проверяет структуру, metadata и hash. Устанавливайте только доверенные плагины; применяйте staged files вручную при остановленном сервере после резервной копии. Restore активных миров и автоматический reload не выполняются.

Сессии, HTTP и SQL не проходили внешний penetration audit. Тесты и найденные/исправленные случаи описаны отдельно в `TESTS.md`.
