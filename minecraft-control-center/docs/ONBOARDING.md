# MCC 0.10 — первый запуск

Плагин создаёт владельца по настоящему имени и UUID Minecraft игрока. Параметры браузера не могут назначить произвольного владельца. При новой установке публичного логина/пароля нет.

1. Установить MCC JAR и запустить совместимый сервер.
2. Войти в Minecraft с OP или `mcc.setup`. Личная ссылка появляется в чате. `/mcc setup` выдаёт новую; консольная `mcc setup <onlinePlayer>` отправляет ссылку только этому авторизованному игроку.
3. Открыть ссылку и оставаться онлайн. Срок — 10 минут. Ник уже подтверждён Bukkit. Выбрать пароль 12–128 символов, пресет и доступ.
4. Просмотреть изменения и открыть панель. MCC Core можно подготовить здесь или позднее в настройках. Замена ядра требует следующего штатного запуска.

Новые установки используют web TCP-порт `8123`; явно настроенные прежние порты и номер, выданный хостингом, сохраняются. На удалённом сервере перед первой ссылкой задайте `web.public-origin` с настоящим адресом панели или HTTPS reverse proxy в `config.yml`, затем штатно перезапустите сервер. При пустом значении ссылка использует `http://localhost:<port>`: автоматическое определение публичного hostname/port mapping не реализовано. Token в URL fragment не копируйте в открытые логи и отчёты. [Настройка порта и внешнего адреса](HOSTING-PORT.md), [HTTPS и безопасность](../SECURITY.md).

Мастер имеет четыре шага с адаптивной разметкой, Minecraft-маяком, переходами Motion, keyboard focus и reduced-motion. Если ссылка просрочена или уже использована, мастер объясняет, как получить новую. Reload возобновляет действующую setup cookie.

## Защита первого владельца

Случайный 256-bit token находится только в fragment URL и не попадает в обычную HTTP request line. Интерфейс стирает fragment перед загрузкой данных. Сервер хранит hash capability в ограниченной временной памяти; после claim ссылка одноразово потребляется. Setup cookie HttpOnly/SameSite Strict, изменяющие запросы требуют текущий CSRF и правильный Origin. После перезапуска ссылки недействительны.

Право OP/`mcc.setup`, онлайн-состояние, имя и UUID проверяются при claim, подготовке пресета и завершении; полномочия повторно проверяются после Argon2, перед транзакцией. Одновременно создаётся только один Owner. Ник в POST не принимается. Owner, лицензия и параметры первого запуска сохраняются одной SQLite-транзакцией. Сам пароль хранится как Argon2 hash.

Если сохранение пользователя прошло, но применение пресета или подготовка Core не завершились, API честно возвращает состояние конфигурации: владелец уже может войти и повторить операцию в настройках. Созданный аккаунт не теряется из-за ошибки установки ядра.

## Доступ панели

| Режим | Возможности |
| --- | --- |
| Пробная версия | Обзор с текущими метриками, консоль, чат, настройки |
| Временная полная версия | Все доступные функции MCC, без ввода ключа |
| Лицензионный ключ | Интерфейс есть; активация ещё не реализована, произвольные ключи отклоняются |

Пробные ограничения работают в HTTP API, очереди действий и WebSocket, а также выключают оплачиваемые фоновые модули: карту, события, автоматизации, монитор руды, интеграции и подробные снимки. Отключение не стирает сохранённые данные. Owner recovery API резервных копий остаётся доступным, чтобы не лишать владельца возможности восстановиться. Настройки сохраняют предпочтения модулей отдельно от эффективных ограничений лицензии.

Настройки → «Версия панели» позволяет Owner переключить временный режим с подтверждением и CSRF. Это локальный прототип лицензирования, без удалённой проверки и защиты от модификации серверных файлов. Консоль остаётся инструментом администратора сервера; лицензирование не является границей доверия от его оператора.

## Обновление прежней установки

Действующие изменённые аккаунты и аудит сохраняются. Только единственный известный legacy Owner `admin`, помеченный как исходный и всё ещё использующий публичный пароль, проходит первый запуск заново: запись переименовывается в настоящий Minecraft ник и получает выбранный сильный пароль. При нескольких пользователях исходный слабый аккаунт остаётся ограниченным обязательной сменой пароля. MCC не удаляет неизвестные пользовательские аккаунты.

Для прежней настроенной установки без сохранённого режима лицензии действует временная полная версия. Не запускайте исторический `Migrate-Local-Admin.java` для возвращения default credentials.

## API

| Запрос | Назначение |
| --- | --- |
| `GET /api/setup/status` | Требуется ли первый запуск; с setup cookie — подтверждённое имя, CSRF, срок, пресеты и статус Core |
| `POST /api/setup/claim` `{token}` | Потребляет ссылку, выдаёт setup cookie |
| `POST /api/setup/profile-plan` `{profile}` | Создаёт действующий план пресета, привязанный к этой setup-сессии |
| `POST /api/setup/complete` | Сохраняет пароль, `profile`, `planId`, `confirmed:true`, `licenseMode`, пустой `licenseKey` и `core:keep|mcc-core` |
| `GET/POST /api/license` | Статус и подтверждённое изменение режима Owner |
| `GET /api/server/core` | Фактический статус привязки/установки ядра |
| `POST /api/server/core/stage` `{confirmed:true}` | Подготовка проверенного JAR и offline-plan; не перезапускает сервер |

Вводящий/неверный token, Origin, CSRF, недействующий план, истёкший срок, потеря OP и повторное создание Owner отклоняются. Ник и UUID не передаются клиентом для завершения.

## Состояние обновлённого Main

Точный 8ff5 MCC 0.10 установлен после normal stop и закрытой копии 10 109 файлов / 485 425 076 байт с тремя SQLite базами. Deployment `6a1d972cebcb809138156432885d0e949e44f49e92f0d5d21068a435d17ac6b3` и independent liveness `b9ebda6c3df4039c1f70878a6c8bbef2e3e9520e094c646242075666b71e1c2a` — PASS: прежний Paper 26.3, явный порт 8080, прежние JVM flags, сервер оставлен включённым. Core на Main автоматически не устанавливался. Три world UUID и семь configuration SHA pins сохранены; в `server.properties` допускается только известная вторая generated timestamp строка, все остальные байты сравниваются точно. Закрытая LuckPerms H2 копия точна; live logical rows внешним read не проверялись.

Main browser receipt `baf578a6e14d97be25ad8d5578f24fce44a273b37416a7e6e08f476cc2c2189d` подтверждает first-run waiting screen, `setupRequired:true` и отсутствие доступного default admin. Root не создавал Main Owner и не заполнял auth fields. Владелец должен войти в Minecraft с OP/`mcc.setup`, открыть личную ссылку и завершить мастер сам. Это не свидетельство завершённого нового browser wizard.

Workload performance завершена INCOMPLETE: три из девяти measured boots штатно закрыты, полных трёх парных серий и confidence intervals нет. Остановка по ресурсам стенда не является crash Core и не доказывает его превосходство. [Частичные workload-результаты и ограничения](PERFORMANCE-COMPARISON.md) сохранены отдельно.
