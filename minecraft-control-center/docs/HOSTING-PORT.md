# Web-порт MCC на Minecraft-хостинге

Новые установки MCC используют TCP-порт `8123`, как стандартный `webserver-port` в [официальной конфигурации Dynmap](https://github.com/webbukkit/dynmap/blob/v3.0/spigot/src/main/resources/configuration.txt#L335-L336). Хостинг может выделить другой номер: в этом случае используйте именно выданный хостингом TCP-порт для web-панели/Dynmap.

В `plugins/MinecraftControlCenter/config.yml` параметр `web.port` задаёт фактический порт MCC. Например, для выделенного хостингом `7229`:

```yaml
web:
  host: 127.0.0.1
  port: 7229
  allow-lan: false
  public-origin: ''
  secure-cookie: false
```

Этот пример сохраняет локальный доступ. Для внешнего доступа настройте адрес прослушивания, разрешённый публичный origin и HTTPS по [SECURITY.md](../SECURITY.md). При HTTPS reverse proxy внешний адрес может использовать `443`, а MCC за прокси — выделенный внутренний порт. Перед выдачей первой персональной ссылки настройте `web.public-origin` на настоящий адрес панели: плагин не угадывает публичный hostname или port mapping.

После изменения порта штатно перезапустите Minecraft-сервер. Сохраните предыдущий `config.yml` для отката. Настройки безопасности, Host/Origin-проверки, сессии и CSRF действуют на любом выбранном порту.

Обновление MCC не переписывает существующий `config.yml` и не меняет явно указанный порт. Прежний `8080`, порты тестовых серверов и любой допустимый номер хостинга сохраняются. Если `web.port` отсутствует, используется `8123`; плагин не записывает этот fallback поверх существующего файла. Допустимый диапазон — `1024–65535`.

Два web-сервера не могут одновременно слушать один TCP-адрес и порт. Если на выделенном адресе/порту уже работает Dynmap, задайте одному из плагинов отдельный доступный порт либо явно отключите встроенный web-сервер Dynmap (`disable-webserver: true`) в его конфигурации. Сам MCC конфигурацию Dynmap не изменяет. При конфликте MCC сообщает адрес и порт в серверном журнале и предлагает проверить выделенный порт; он не занимает случайный запасной порт. Если нужен совместный внешний порт для двух web-сайтов, настройте reverse proxy с отдельными hostname и разными внутренними портами.

Открытый Dynmap-порт не отменяет сетевые правила хостинга. Проверьте в его панели фактическую TCP allocation/переадресацию; MCC не изменяет firewall и не создаёт allocation самостоятельно.
