# Локальный администратор0.6

На новой пустой loopback-установке `auth.bootstrap-admin:true` создаёт только admin/admin с ролью Owner. В интерфейсе это «Администратор панели». После входа показывается уведомление о начальном пароле и кнопка профиля. Пользователи, создаваемые вручную, требуют пароль12–128символов. Новая LAN/proxy-установка либо `bootstrap-admin:false` использует закрытый одноразовый `.setup-token`.

Начальный пароль имеет постоянную отметку `auth-default-account`. TCP source должен быть loopback, bind loopback, allow-lan false и public-origin пустым. При переименовании отметка переносится; при смене на новый пароль она снимается. Уведомление не раскрывает реальные пароли. Маркер `auth-bootstrap-admin-v1` предотвращает повторное создание admin после удаления/переименования.

В настройках Owner может добавлять и удалять пользователей. Подтверждение удаления показывает конкретный логин. Нельзя удалить текущую запись или последнего Owner. Сервер повторяет эти проверки внутри транзакции и отзывает сессии; параллельные удаления не могут оставить панель без Owner. Audit/история сохраняются.

Обычное обновление сохраняет существующую SQLite базу. Разовая смена конкретного локального owner на admin/admin — отдельная разрешённая операция после штатной остановки, закрытой резервной копии и проверки исходного состояния. Остальные установки автоматически не сбрасываются. Перед публикацией LAN/HTTPS владелец задаёт собственный сильный пароль в профиле.

Внешний deployment controller обязан удерживать эксклюзивный supervisor/offline lock от normal stop до окончания миграции и замены JAR. `FileChannel.tryLock` внутри Java utility — дополнительный краткий probe, а не lease на всё время JDBC-транзакции. Копия должна быть отдельным файлом: hardlink/alias исходной базы запрещён. Проверки строки и default marker выполняются до commit.
