# Граф автоматизаций 0.3

Граф хранится в SQLite namespace `automations` вместе с координатами редактора. Доступ имеют Admin и Owner. Сервер выполняет только известные типы действий: `chat.broadcast`, `player.message`, `player.give`, `player.title`, `player.actionbar`, `player.sound`, `player.effect`, `player.firework`, `world.time`, `world.weather`. JavaScript, команды консоли, OP и управление сервером через граф отсутствуют.

## HTTP

| Метод | Путь | Результат |
|---|---|---|
| GET | `/api/automations` | Сохранённые графы; старые правила представлены графами |
| GET | `/api/automations/catalog` | Типы, allowlist и ограничения |
| POST | `/api/automations` | Проверка и сохранение полного Graph DTO |
| DELETE | `/api/automations/{id}` | Удаление и отмена оставшихся узлов активного запуска |
| POST | `/api/automations/{id}/run` | `{id: requestUUID, confirmed:true, context:{world?,uuid?}}`; начальный Run DTO |
| GET | `/api/automations/runs/{runId}` | Текущее состояние запуска |
| GET | `/api/automations/{id}/runs?limit=10` | Последние запуски; limit 1–50 |
| GET | `/api/automations/{id}/export` | Старое правило только для представимого графа trigger→action |

POST сохраняет граф, включая `enabled`, `world` и `cooldownSeconds`. Автоматические события выполняют только enabled-графы, ручная кнопка может проверить выключенный граф. Ручной запуск всегда требует явное подтверждение. UUID запроса обеспечивает повтор без второго запуска. CSRF и обычная авторизация обязательны.

## Graph DTO

```json
{
  "id": "c94a49d4-9ba5-4949-a4f9-2ba09bbcb67d",
  "name": "Время при пустом сервере", "enabled": false, "world": "world",
  "cooldownSeconds": 30, "graphVersion": 1,
  "nodes": [
    {"id":"start","type":"trigger","config":{"trigger":"interval","intervalSeconds":30},"pos":{"x":0,"y":0}},
    {"id":"if","type":"condition","config":{"condition":"onlineCount","operator":"eq","value":0},"pos":{"x":240,"y":0}},
    {"id":"day","type":"action","config":{"action":"world.time","params":{"time":6000}},"pos":{"x":480,"y":0}}
  ],
  "edges": [
    {"id":"1","source":"start","target":"if","sourceHandle":"next"},
    {"id":"2","source":"if","target":"day","sourceHandle":"true"}
  ]
}
```

Один trigger: `join`, `quit`, `death`, `interval`. Интервал и cooldown: 30–86400 секунд. Граф содержит до 32 узлов и 64 связей, минимум одно действие. Все узлы достижимы из единственного trigger; циклы, повторяющиеся связи, неизвестные узлы и незакреплённые концы отклоняются. У condition разрешены выходы `true` и `false`, у остальных `next`. Координаты pos конечные, от -10000 до 10000. Документ не больше 64 KiB.

Conditions: `onlineCount` (0–100000), `tps` (0–20), `worldTime` (0–23999), `weather` (`clear|rain|thunder`), `playerOnline` (boolean, optional canonical UUID). Числовые сравнения: `eq/ne/lt/lte/gt/gte`; для weather/playerOnline — `eq/ne`. Входной alias `neq` сохраняется как `ne`. Отсутствующий operator означает `eq`. World/UUID берутся из config, затем контекста события; world может наследоваться из поля графа. Пустые UUID необходимо удалить из DTO. Проверки условий и игровых реестров идут на основном потоке Paper. MCC не подгружает миры или chunks для условия.

TPS condition читает сырое значение Bukkit, которое иногда немного превышает 20; число 0–20 ограничивает порог условия. Dashboard отображает TPS с верхним пределом 20. Для рабочих сценариев предпочтительнее порог вроде `gte 19`, чем точное `eq 20`.

Interval не содержит игрока: для автоматических `playerOnline` и `player.*` задайте UUID явно. Ручная проверка может взять UUID выбранного игрока. События join/quit/death передают UUID и мир события; после quit игрок уже может быть offline, поэтому действие, которому нужен онлайн-игрок, завершится ошибкой. Проверяйте это условием playerOnline.

`delay` использует `config.seconds` 0.05–60. Сумма всех задержек графа не больше 60 секунд; общий deadline 90 секунд. Действия используют параметры обычного GameService API, включая метаданные `player.give.item`. Для эффекта параметр `duration` измеряется в ticks, для погоды — `durationTicks`.

## Порядок и история

Узлы идут в топологическом порядке. Условие активирует только выбранный выход. Неактивные ветки получают `skipped`. Узел с несколькими входами выполняется один раз, если активирован хотя бы один вход. Несколько действий и fan-out разрешены; действие следующего узла начинается после результата предыдущего. Ошибка прекращает оставшиеся действия; уже выполненные изменения автоматически не откатываются.

Run DTO: `runId`, `ruleId`, `name`, `actor`, `status`, `createdAt`, `finishedAt`, `nodes`, optional `error`. Статусы запуска: `queued/running/completed/failed/cancelled`; статусы узла: `pending/running/completed/skipped/failed/cancelled`. Узлы содержат `id`, `type`, timestamps и ограниченный `result` либо `error`. WebSocket topic `automation` передаёт состояние по мере выполнения. История до 200 запусков хранится в SQLite namespace `automation-runs`; при старте незавершённые запуски помечаются cancelled и не продолжаются.

Штатный shutdown сохраняет cancelled и timestamps активной задержки до закрытия базы. При аварийном прерывании записанный queued/running помечается cancelled на следующем старте. Подтверждённые завершённые узлы сохраняются; оставшиеся действия не возобновляются и заново не выполняются. Эта отмена не отменяет уже применённые игровые изменения.

Одновременно разрешено четыре запуска, по одному на граф. Повтор ручного запуска одного графа возможен через секунду; HTTP дополнительно ограничивает 10 запусков в минуту на аккаунт. Задержки не занимают основной игровой поток. Запись истории идёт через ограниченную очередь SQLite. Удаление, выключение модуля и shutdown отменяют оставшиеся узлы. Если игровой узел уже начал работу и не может быть отменён, Run DTO содержит `effectMayComplete:true`: его действие может закончиться, но следующие узлы не запускаются.

Счётчик `automationErrors` учитывает как failed, так и cancelled; штатная отмена задержки поэтому тоже увеличивает его. Оценивайте причину по status/error конкретного запуска.

Старые записи при чтении преобразуются в trigger→action без автоматической перезаписи SQLite. World, enabled, параметры и прежний cooldown сохраняются. Экспорт сложного графа в старый формат отклоняется, чтобы не терять ветки или действия.
