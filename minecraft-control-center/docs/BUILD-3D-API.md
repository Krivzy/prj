# Архив: прежняя 3D карта и строительство

В MCC0.5 карта доступна только для просмотра на Canvas2D. Весь namespace `/api/build` и бывшие `/api/map/detail`, `/api/map/region` retired: authenticated410/anonymous401; BuildEngine удалён. Текущий surface/index контракт и лимиты описаны в [API.md](../API.md). Ниже сохранена историческая документация ранней карты; она не описывает доступные сейчас endpoints.

## Прежняя 3D карта и строительство

Карта читает реальные `BlockData` Paper на основном потоке. Она не загружает и не генерирует чанки. Незагруженная ячейка — `null`; воздух — отдельный элемент palette с `air:true`. Некоторые декоративные формы в браузере упрощены до кубов. Срез Y влияет только на изображение.

## Область

`GET /api/map/region?world=world&x=0&y=64&z=0&size=16`

```json
{"world":"world","worldId":"UUID","origin":{"x":-8,"y":56,"z":-8},"size":16,"blocks":[0,null,1],"palette":[{"blockData":"minecraft:air","material":"AIR","color":"#000000","occluding":false,"air":true}],"players":[],"loadedOnly":true,"loadedBlocks":2048,"totalBlocks":4096,"sampledAt":0}
```

В настоящем ответе `blocks.length == size³`; индекс `x + size * (z + size * y)`, координаты относительно origin. `size` от 8 до 32. Y origin ограничен высотой мира. Максимум 4 запроса карты одновременно, до 256 блоков и 1 ms работы на тик суммарно; при TPS < 18 чтение приостанавливается. Таймаут 20 s. Снимок читается порциями и не представляет атомарное состояние всего мира. Строительство отдельно проверяет актуальность каждого блока.

Сервер раздаёт собственный `/game-assets/catalog.json` и PNG Minecraft. Браузер использует `blocks[key].faces` и `image`, а при отсутствии текстуры — настоящий map color блока. Никаких выдуманных участков мира нет.

## Предпросмотр

`POST /api/build/preview` требует Admin/Owner и CSRF. Координаты — целые, границы включены.

| operation | Параметры |
|---|---|
| place | `world, min:{x,y,z}, blockData`; max отсутствует или равен min |
| remove | `world, min:{x,y,z}`; заменяет одним air без дропа |
| fill | `world, min, max, blockData`; заполненный параллелепипед |
| line | `world, min, max, blockData`; линия между заданными точками |
| box | `world, min, max, blockData`; оболочка параллелепипеда |
| sphere | `world, min, max, blockData`; заполненный эллипсоид в границах |
| copy | `world, min, max`; только читает и сохраняет личный буфер |
| paste | `world, origin:{x,y,z}, rotation:0/90/180/270`; личный буфер включая воздух |
| undo/redo | `world`; последняя запись личной истории должна относиться к этому миру |

`blockData` — строка Paper, например `minecraft:oak_stairs[facing=east]`. Состояния повёрнутых блоков при paste также поворачиваются через публичный Paper API.

Ответ обычного preview: `{token,operation,changes,affected,bounds:{min,max},expiresAt,requiresConfirmation,loadedOnly:true}`. Токен живёт 60 s, привязан к пользователю, точным параметрам и исходным состояниям. Undo/redo дополнительно привязан к ID конкретной записи истории. При изменении истории нужен новый preview.

Copy сразу возвращает `{operation:"copy",copied,bounds,clipboard:{blocks,size},loadedOnly:true}` и не требует второго POST. Буфер ограничен 4096 блоками и хранится в памяти; перезапуск очищает буфер.

## Выполнение

`POST /api/build/actions` повторяет те же параметры и добавляет `id` UUID, `previewToken`, `confirmed` boolean. Более одного фактически изменяемого блока требует `confirmed:true`. Все изменения, включая один блок и undo/redo, требуют preview. Повторный ID с теми же параметрами возвращает существующую операцию; другой пользователь или параметры отвергаются.

Ответ HTTP использует общий tracked envelope MCC: `{ok:true,result:{jobId,status:"queued",...}}`. При ожидающем основном потоке ответ может иметь `pending:true`; опрашивается `GET /api/actions/<id>`. Далее `GET /api/build/jobs/<jobId>` возвращает `status`, `changed`, `skipped`, `total`, `progress`, `message`, `startedAt`, `finishedAt`. Статусы `queued`, `validating`, `saving`, `running`, `paused`, `completed`, `partial`, `failed`. Очередь не считается завершённым изменением мира.

## Ограничения и восстановление

- Максимум 4096 блоков в bounding volume (включая пустые ячейки) для fill/box/sphere/copy, стороны до 64; line до 64 блоков. До 4 активных операций глобально, одна на пользователя. Пересекающиеся записи MCC не запускаются одновременно.
- Все позиции должны находиться в высоте и border мира, в уже загруженном чанке. Каждый read/write повторно проверяет загрузку; никакого force loading.
- Точная безопасность данных: изменение или размещение любого `TileState` запрещено. Поэтому контейнеры, знаки, головы, спавнеры и прочие блоки с данными/NBT не теряют содержимое; они не поддерживаются этим редактором.
- Защищены жидкости, waterlogged, гравитационные блоки, не-solid растения/декор, составные Bisected/Bed, поршни, порталы, TNT, bedrock/barrier, command blocks, light/structure void, respawn anchor, dragon egg. Одиночные Stairs и TrapDoor разрешены: их Bisected означает положение half, а не второй блок. Проверяется как текущий, так и новый блок. Каталог показывает весь Minecraft; сервер явно объясняет отказ для неподдерживаемого блока.
- Установка выполняется `setBlockData(data,false)`, без дропов и массовой физики. Это административный инструмент и не имитирует действия Minecraft-игрока или чужие region-claim плагины.
- На тик: до 128 проверок, 32 записи и 1 ms общего времени; при TPS < 18 запись ставится на паузу. Таймаут операции 60 s. Отключение модуля отменяет будущую работу; уже сделанные блоки остаются в истории.
- Перед первой записью сохраняется protected write-ahead journal с полными исходными/целевыми строками BlockData. Поток Paper не делает файлового I/O: callback ставит запись в асинхронную БД, engine ждёт future.
- Undo/redo меняет блок только при точном совпадении ожидаемого состояния. Уже восстановленные блоки пропускаются. Чужое изменение даёт конфликт и не перезаписывается. Внешний конфликт между порциями может дать `partial`; фактически изменённое количество возвращается явно.
- После прерывания журнал содержит полный план. Undo пропускает ячейки, которые ещё не успели измениться. При прерывании undo/redo переход истории уже записан; следующая противоположная операция может восстановить исходное согласованное состояние, также проверяя каждый блок. Автоматического восстановления мира при запуске нет.
- Личная история: до 10 записей и 8192 ячеек. В памяти до 16 пользователей; сервер подгружает сохранённую историю по cache miss. Job results хранятся до 10 min, максимум 128 завершённых записей.

Java lifecycle: `BuildEngine(plugin,events)`, `enabled(boolean)`, `setPersistence(BiFunction<String,Map<String,Object>,CompletableFuture<Void>>)`, `restoreHistory(actor,document)`, `hasHistory(actor)`, `preview(actor,params)`, `execute(actor,id,params,confirmed)`, `job(actor,id)`, `history(actor)`, `close()`. Все вызовы на Bukkit main thread. Только persistence future завершается асинхронно.

## Потоковая карта 0.3

`GET /api/map/index?world=...` читает Anvil location headers асинхронно, до 2048 файлов регионов. Возвращает `{world,regions:[{rx,rz,chunks,presence}],savedChunks,bounds,truncated,scannedAt}`. `presence` — Base64 bitmap из 128 bytes: bit `x + 32*z` обозначает сохранённую запись чанка. `bounds` содержит координаты чанков, а не блоков. Сохранённая запись может быть protochunk: индекс показывает сохранённое покрытие; ландшафт читает только полностью сформированные чанки. Это обзор существующего сохранённого мира, а не обещание загрузить бесконечный мир разом.

`GET /api/map/terrain?world=...&cx=...&cz=...&radius=2&step=1` доступен авторизованным пользователям. `cx/cz` произвольны в пределах Minecraft, радиус 0..3, до 49 чанков в viewport. Возвращает реальные `{tiles,players,pending,metrics,limits}`; состояния чанка `loading/processing/ready/deferred/missing/error`. Для `ready`: `heights[256]`, `voxels[3072]`, `palette` точных BlockData. Индекс колонки `x + 16*z`, слоя `column + 256*depthOffset`; верхние 12 слоёв читаются из ChunkSnapshot. Отсутствующие данные не подменяются придуманными блоками. HTTP 202 при `pending:true` содержит полный DTO viewport и не означает строительную операцию.

Terrain использует официальное `getChunkAtAsync(cx,cz,false,false)`: только существующие чанки, без генерации. До двух async loads, 64 pending/cache entries, 8 MCC tickets глобально. Снимок создаётся на main thread, максимум один за тик при TPS >= 18; общий стартовый бюджет 1 ms является мягким ограничением, отдельный вызов Paper не прерывается. Обработка thread-safe ChunkSnapshot и чтение файлов выполняются отдельным bounded worker. Surface tickets освобождаются после снимка; снимки кэшируются 120 s. Cache invalidation после MCC строительства и запроса detail не позволяет старому worker result воскресить старую плитку.

`GET /api/map/detail?world=...&x=...&y=...&z=...&size=16` доступен Owner/Admin. Загружает только существующие чанки детальной области (size8..16, до4 чанков), временно удерживает их MCC plugin tickets до45 s. Один pending detail на пользователя; переход освобождает старые leases. Возвращает исходный точный volumetric DTO `/api/map/region`. Отключение карты/плагина отменяет pending задачи и освобождает принадлежащие карте tickets; сервер выгружает чанки своим обычным механизмом.

`GET /api/build/catalog` возвращает `{blocks:[{material,blockData,supported,reason}],maxBlocks}`. `supported` использует тот же safety validator, что и реальное строительство. Контейнеры, жидкости и другие неподдерживаемые материалы отключены в палитре с объяснением. Предпросмотр всё равно повторно проверяет конкретное текущее и новое состояние блока.

Редактор: ЛКМ по свободной грани ставит соседний блок, ПКМ убирает выбранный блок; Ctrl+click только осматривает. Перемещение мыши свыше5 px управляет камерой и не считается строительным кликом. Каждый одиночный клик проходит detail → preview → execute → job acknowledgment; показанный мир обновляется реальным снимком после завершения. Массовые формы используют отдельный preview и подтверждение. При уходе со страницы новые POST не стартуют и browser polling прекращается; ID уже отправленной операции сохраняется для восстановления результата.

Официальные API: [Paper World async chunks](https://jd.papermc.io/paper/26.3/org/bukkit/World.html), [thread-safe ChunkSnapshot](https://jd.papermc.io/paper/26.3/org/bukkit/ChunkSnapshot.html), [Chunk plugin tickets](https://jd.papermc.io/paper/26.1.2/org/bukkit/Chunk.html). NMS не используется.

Классические grayscale-текстуры листвы и верхней грани травы окрашиваются приблизительными фиксированными цветами. Это не точные biome tints; цветные листья azalea/cherry/pale oak и боковые грани травы сохраняют исходную текстуру. Перекрывающиеся запросы detail сохраняют свои chunk leases; Paper callback закрепляет загруженный FULL-чанк до передачи следующему scheduler tick, чтобы idle-чанк не исчез между запросом и строительством.

### Проверка финальной сборки 0.3

Paper 26.3, JAR SHA-256 `4405736350d4e8803211169ecb96b31c851f5b9f4a896502fe1c8e9f6689ce7e`: `reports/MAP-V3-E2E.json` подтверждает 23/23 проверки в одноразовом loopback-стенде. Обычный левый клик создаёт один настоящий STONE; правый удаляет его. Undo/Redo, fill8, copy8 и paste8 с rotation90° проверены по фактическим BlockData и полностью отменены. Пять повторных detail сохраняют overlapping leases; после47 секунд без detail все plugin chunk tickets освобождены (0), pending0/loads0. Проверены farFULLchunk32,32, переход камеры к512,512, mobile390px и отсутствие файла конкретного несозданного remote-региона до/после GET. Native генерация far-стенда выполнялась явно отдельно; глобальное число сохранённых чанков могло меняться из-за Paper и не является доказательством no-generation. Карта не превращает сохранённые PROTO-чанки в FULL.

`MCC-v3-map.png` показывает обычный ландшафт безdetailoverlay; `MCC-v3-world-editor.png` оставлен как отдельная техническая иллюстрация точного объёма. После изменения cache карты инвалидируется: пока новые снимки читаются, кадр может временно содержать только часть terrain; индикатор показывает ready/total и загрузку. Exact overlay не удаляет реальные блоки мира.

### Исправления дополнительного визуального аудита

При обновлении карты последний полный снимок плитки остаётся видимым до готовности следующего и помечается «обновляем». Это не применяется к настоящему `missing`/неполностью созданному PROTO-чанку либо к другому миру. Admission резервирует до8 tickets с учётом ещё выполняющихся загрузок; готовые уже удерживаемые чанки допускаются к повторному чтению. Временные capacity/I/O ошибки возвращаются как `deferred`/`error` с коротким retry, а не как отсутствующая местность на30 секунд.

Классическая animated water PNG также grayscale: добавлен приблизительный фиксированный синий tint. Маркеры игроков обновляются независимо от возраста terrain snapshot. Режим «Исследование» скрывает строительные инструменты, историю и предпросмотр, убирает detailoverlay и сбрасывает выбор второго угла. После перехода в него ожидавшее чтение/предпросмотр не начинает новую запись; уже отправленная операция продолжает завершение и доступна в редакторе.

Для прямоугольной области не более16 блоков по каждой оси detailleases читаются вокруг центра bounds; paste учитывает повёрнутый размер clipboard. Большие области по-прежнему требуют уже загруженных чанков и не расширяют лимит4 detailchunks автоматически. Панорамирование камеры сохраняет абсолютное положение pendingghost. После частичного/неуспешного job обновляется история, чтобы новая доступная Undo не оставалась скрытой.
