# Арт-дирекция и композиция

Читай при создании или существенной переработке визуального образа. Это набор способов принять решение, не каталог стилей для случайного выбора.

## Связь образа с задачей

Сначала сформулируй предложение: «Эта страница показывает ___ через ___, чтобы человек мог ___». Подбери реальную фотографию, продуктовый пример, факт или демонстрацию, которые поддерживают это предложение. Если поменять логотип и тексты другого бизнеса и ничего не придётся менять, проверь, достаточно ли решения связаны с продуктом.

Для нового направления достаточно сравнить несколько действительно разных вариантов. Отличие — в способе подачи содержания и визуальном ритме, а не только в оттенке gradient. Пользовательский reference и ограничения бренда имеют приоритет.

| Направление | Подходящий материал | Контроль качества |
| --- | --- | --- |
| Крупная типографическая афиша | Короткое сильное сообщение, запуск, культурное событие | Заголовок читается при масштабировании; поддержка и действие не исчезают |
| Предметная витрина | Форма, фактура, качество продукта | Деталь изображения действительно показывает преимущество; ясный CTA |
| Редакционная история | Статья, портфолио, исследование, документальный материал | Разный масштаб разделов следует значимости; подписи и сетка поддерживают чтение |
| Живая демонстрация | Инструмент, SaaS, визуальный продукт | Demo помогает понять результат, имеет доступный текстовый эквивалент |
| Пространственный рассказ | Архитектура, предмет, инсталляция | 3D объясняет структуру; у пользователя сохраняется управление и fallback |

## Типографическая система

- Проверь реальные языки, наборы glyphs, доступные начертания, лицензию и способ загрузки. Не предполагай наличие кириллицы у красивого display-font.
- Назначь роли: display, заголовки, body, UI, данные. Одна семья может обслуживать несколько ролей; вторая нужна при функциональном различии, а не по правилу «всегда два шрифта».
- Определи размеры, line-height, ширину строки, tracking и вес через tokens. Для body стартовая мера около 45–75 знаков помогает чтению, но проверяй реальное содержание и язык.
- Display можно сделать частью композиции: значимый масштаб, ритм строк, variable width, оптическая связь с изображением. Не деформируй буквенные формы через `scaleX` ради посадки в строку.
- Не вставляй `<br>` на каждом breakpoint. Редакционный перенос допустим для короткого заголовка, если устойчив к другим языкам, text zoom и fallback-font.
- `clamp()` с `rem` и viewport-компонентом помогает fluid scale; одной формулы недостаточно для доступности. Проверь 200% text enlargement и reflow при эквиваленте 320 CSS px; чистый `vw` может мешать увеличению.
- Загрузка: несколько нужных WOFF2-начертаний или оправданный variable-font, корректный fallback; preload только действительно критичного файла. Hero не должен ждать всех начертаний.

## Ритм и разнообразие разделов

Разбери контент на роли: обещание, доказательство, объяснение, сравнение, процесс, действие. Выбирай форму каждой роли. Большой тезис не требует карточки; длинная история не требует bento; сравнительным данным часто подходит таблица. Сохраняй общие tokens и повторяй форму там, где повторяется смысл.

Композиционные инструменты:

- Контраст масштаба: один главный объект, более спокойные подписи и поддержка.
- Асимметрия в устойчивой сетке: смещение визуального объекта не меняет DOM/reading order.
- Negative space: расстояние показывает группировку и важность; пустота не должна делать действие труднодоступным.
- Изображения разного масштаба: показывают контекст и деталь; crops сохраняют значимый объект на каждом размере.
- Типографический rhythm: меньше разновидностей начертаний и больше ясных ролей.
- Структурные линии, номера, метки: вводи только если они кодируют реальное отношение, последовательность или тип данных.

Не заменяй универсальный gradient/cards одним другим универсальным preset вроде «чёрный фон + кислотный акцент». Минимализм, rounded cards, bento, glass и редакционная сетка уместны при связи с задачей. Ни один из них не является обязательным или запрещённым.

## Кинематографический hero

Драматургия hero включает понятное исходное состояние, акцент и устойчивое конечное состояние. Пользователь сразу может прочитать сообщение и перейти к действию. Не делай обязательный loader, screen takeover или intro с задержкой навигации.

1. Выбери главный носитель идеи: текст, фото, короткое видео, SVG, demo или 3D.
2. Укажи фокальную точку и безопасную область для текста в desktop/mobile crop.
3. Определи последовательность, если она нужна: например, общий вид → важная деталь → доступное действие. Анимация не является единственным способом получить доказательство.
4. Обеспечь начальную зарезервированную геометрию и явный fallback при задержке медиа.
5. На маленьком/слабом устройстве сохрани сюжет через более простой кадр. Уменьшение качества должно быть управляемым, не случайным.
6. Видео с существенным смыслом требует controls/альтернативу; беззвучный декоративный loop — pause policy и reduced motion. Не скрывай CTA на время ролика.

## Навигация как часть концепции

Полноэкранное меню, боковая лента, типографический список и overlay-preview могут быть выразительными, пока люди находят разделы. `nav` содержит обычные ссылки, раскрытие запускает `button` с `aria-expanded`/`aria-controls`. Для обычной web-навигации не добавляй роли `menu/menuitem`: они означают другой keyboard pattern.

Disclosure — не модальный dialog по умолчанию. Если дизайн действительно блокирует остальную страницу, реализуй modal lifecycle, Escape, управление focus и возврат к opener через проверенную компонентную библиотеку. Покажи одинаковые действия на keyboard и touch; hover-preview дополняет ссылку.

## Самопроверка до и после браузера

- Концепция объясняется через продукт и подтверждается содержанием.
- Самый выразительный элемент — самый значимый, а не случайная фоновая форма.
- Тексты выглядят как содержание интерфейса, а не техническое описание реализации.
- Пустые и ошибочные состояния помогают действовать и сохраняют visual hierarchy.
- Screenshot показывает выровненные оптические края, устойчивые gaps и читаемые строки; сравнение с desktop не сводится к уменьшению всего макета.
- Визуальные решения сохраняются без custom cursor, blur, WebGL и intro.

## Проверенные источники

Проверены 2026-10-10. Не фиксируют совместимость навсегда; перед применением новой browser-функции проверь targets проекта.

- [MDN: clamp()](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/clamp) — fluid значения с нижним и верхним пределом.
- [W3C: Resize Text](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html) — увеличение текста до 200% без потери содержания/функций.
- [W3C: Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html) — проверка эквивалента 320 CSS px и исключения для действительно двумерного контента.
- [WAI APG: Disclosure Navigation](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/examples/disclosure-navigation/) — ссылки и disclosure вместо роли application-menu для обычной навигации. APG-example требует проверки в целевой комбинации browser/assistive technology.
