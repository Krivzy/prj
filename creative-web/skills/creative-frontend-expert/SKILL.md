# Creative Frontend Expert

Отвечай за художественную идею и её реализацию в браузере. Цель — характерный для продукта интерфейс с полезным взаимодействием, а не набор эффектов или обещание премии Awwwards.

## Границы и подключение

- Существующий `frontend-design` отвечает за базовую художественную направленность. Прочитай его при новой концепции; сохраняй принятую пользователем стилистику. Этот skill добавляет реализацию сложных композиций и эффектов.
- `ui-ux-pro-max` используй как доступный локальный поиск идей, палитр и продуктовых паттернов, если нужны альтернативы. Результаты поиска — материал для решения, а не обязательный шаблон.
- Для общей системы tokens подключи `ui-ux-design-system-expert`, для переработки раскладки — `responsive-design-expert`. Подключай specialist по GSAP, Motion, Three.js или GLSL только после выбора эффекта. Не загружай все инструкции одновременно.
- Не устанавливай пакет ради выразительности, если эффект можно получить текущим стеком. Сначала изучи имеющиеся компоненты, версии, правила проекта и владение анимацией.

## Перед реализацией

Зафиксируй краткий creative brief в существующей проектной документации либо в плане задачи:

1. Аудитория, основное действие, реальное содержание и характер бренда.
2. Одна идея, которую можно объяснить через предмет проекта: например, смена масштаба деталей материала для мастерской или движение маршрутной линии для путешествия.
3. Типографические роли, сетка, палитра с семантическими tokens, ритм пространства, изображения и один главный выразительный приём.
4. Поведение на desktop, touch и при reduced motion; что останется при недоступном JS/WebGL.
5. Критерий пользы и ограничение стоимости эффекта: размер ресурса, участие main thread, область repaint, сложность обслуживания. Числовой бюджет согласуй с устройствами и проектом, не выдумывай гарантию FPS.

При недостатке некритичных данных делай явные разумные предположения и продолжай. Не превращай подготовку концепции в обязательное согласование каждой творческой детали.

Для арт-дирекции и разновидностей композиции прочитай [art-direction.md](references/art-direction.md). Для конкретного эффекта, CSS/SVG рецептов и lifecycle — [effects-and-lifecycle.md](references/effects-and-lifecycle.md).

## Как выбрать реализацию

| Задача | Предпочтительный механизм | Когда усложнять |
| --- | --- | --- |
| Hover, focus, underline, press, простое раскрытие | CSS transitions/keyframes, semantic HTML | JS только при динамической геометрии/состоянии |
| Маска картинки, векторная линия, узор | CSS `clip-path`/`mask-image`, SVG | Canvas/WebGL для большого числа динамических пикселей |
| Короткая прерываемая DOM-анимация | Web Animations API или уже установленный Motion | Timeline, scrub и сложная синхронизация — GSAP |
| React layout/shared layout, меню, карточки | Motion specialist | Не назначай GSAP владельцем тех же transform/opacity |
| Scroll-story, pinning, синхронная композиция | GSAP specialist | Lenis добавляй только при доказанной пользе |
| Переход снимков состояний/страниц | Поддерживаемый framework API или feature-detected View Transitions | Не вмешивайся в router без проверки back, focus и scroll |
| Интерактивный пространственный предмет | Three.js/R3F specialist | Сначала проверь достаточность фотографии/SVG |
| Сложное искажение/процедурная поверхность | GLSL specialist | Оставь статичный доступный fallback |

Выбранный механизм должен иметь одного владельца состояния и процедуру очистки. Два animation engine могут жить в проекте, но не управлять одновременно одним свойством одного узла. Для разделения используй вложенные wrappers с документированными ролями.

## Реализация по существующей архитектуре

- Сначала сделай рабочую семантическую композицию и главный путь пользователя, затем добавляй визуальные layers. Контент и CTA доступны до запуска анимации.
- Выделяй эффект, навигацию и hero в небольшие модули с явными props и cleanup. Не собирай весь сайт в одном React-компоненте.
- Для контента используй DOM, для декоративных слоёв — `aria-hidden`, `pointer-events: none`. Значимое изображение имеет текстовую альтернативу. Текст не превращай в Canvas ради эффекта.
- Планируй переходы при повторном клике, смене маршрута, resize, загрузке шрифта и прерывании. Состояние приложения меняется независимо от успешного завершения эффекта.
- Cursor-follow, magnetic attraction и hover preview включай только для подходящего pointer; на touch действие остаётся явным. Нативный курсор и keyboard focus не исчезают.
- Motion отвечает на действие или раскрывает смысл. Автозапуск и параллакс не должны прятать информацию, блокировать scroll или мешать чтению. Длительное движение требует доступной остановки.

## Проверка качества

Проверь реальную страницу в браузере после запуска по инструкциям проекта; успешная сборка подтверждает только сборку.

- Главный экран: понятны продукт, контент и действие без ожидания эффекта; характерная композиция сохраняется при узком экране.
- Типографика: реальные тексты, кириллица при необходимости, длинные названия, корректные переносы, fallback и загрузка шрифта без обрезания/резкого скачка.
- Взаимодействия: keyboard, visible focus, Escape и возврат focus в overlay, touch, повторное действие во время анимации.
- Reduced motion: содержательное статичное представление; нет скрытых навсегда reveal-элементов, фиктивного ожидания timeline или обязательного pinning.
- Техника: console без новых ошибок; navigation/back работают; handlers, RAF, observers и timelines освобождаются; профиль показывает реальную стоимость эффекта.
- Композиция: сравни screenshots разных состояний. Удали декоративные слои, которые конкурируют с основным содержанием; одинаковая форма секций оправдана содержанием, а не удобством шаблона.

Если появляется нестабильный scroll, focus или дорогой repaint, уменьши область/число эффектов либо замени механизм и повтори проверку. Отчёт содержит применённую концепцию, владельцев анимации, измерения/проверенные устройства и оставшиеся ограничения.
