# Сохранение и восстановление

После каждой содержательной задачи в GitHub сохраняются код, безопасные
конфигурации, скрипты, документация и нужные для восстановления файлы.
Для задач без кода — полезный Markdown-результат.
Изменений нет: проверить уже опубликованный commit; пустой commit не нужен.

## Перед сохранением

Проверьте аккаунт и доступ, принадлежность проекта, remote, рабочие изменения,
состав файлов и историю, CI/CD и внешние привязки deployment.
Используйте репозиторий проекта; новые создавайте private.
В public публикуйте только явно разрешённый состав данных.
Нельзя добавлять посторонние изменения, credentials, Secrets, .env с секретами,
ключи, закрытые дампы, staging/outbox/sent или полный конфигурационный профиль.
.gitignore не удаляет секреты из уже отслеживаемых файлов и истории.

Выберите ветку без неразрешённых production-действий. Если безопасной ветки
нет, используйте отдельный private-репозиторий без таких привязок.
Автоматического force push, удаления истории или production merge нет.

## Подтверждение

Для обычного push проверьте равенство локального commit SHA и remote ref.
Для server-side commit GitHub-коннектора проверьте remote ref, commit
и все отправленные файлы по blob SHA/хешам; затем можно получить checkout
этого подтверждённого commit. Запишите дату проверки.

В Obsidian Index укажите URL репозитория без credentials, ветку,
полный commit SHA и commit permalink. В тематических заметках используйте
permalink на соответствующие файлы этого commit.
Добавьте зависимости, способ запуска, проверки и восстановление секретов
через закрытые источники; значения секретов в инструкции не включаются.

## Восстановление

Если checkout отсутствует, `git clone <confirmed-url>`, затем получите
и откройте сохранённый commit или рабочую ветку согласно задаче.
Если checkout есть, сначала `git status`, затем `git fetch` и сравнение refs.
Не перезаписывайте локальные изменения и не используйте reset --hard.

Через GitHub-коннектор файлы можно запросить по точному commit SHA.
Полученные файлы образуют рабочую папку; полноценный Git checkout с историей
требует clone/fetch.
Исходники сами по себе не восстанавливают внешние базы данных и секреты:
в Index должны быть указаны отдельные закрытые источники.

## Сбой

При недоступном GitHub сохраните локальный commit или снимок и запишите
pending push с причиной и данными для повторной отправки в Index/Results.
При продолжении сначала проверьте актуальный remote, затем возобновите отправку.
Успешное сохранение объявляется только после удалённой проверки.
