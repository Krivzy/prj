# Структура памяти

Для каждого объекта выберите устойчивую папку: `Projects/<project>/`,
`Infrastructure/<service>/`, `Codex/<topic>/` или `Inbox/Tasks/<task>/`.

```text
<project>/
  Index.md
  Context.md
  Results.md
  Frontend.md    # если есть frontend
  Backend.md     # если есть backend
  Database.md    # если есть база данных
  Deployment.md  # если есть развёртывание
```

Три базовых файла должны быть непустыми. Index содержит краткий статус,
ссылки на модули, canonical GitHub URL, ветку и полный проверенный commit SHA.
Context содержит окружение, требования и решения; Results — выполненное,
проверки, ограничения и открытые шаги. Подробности самостоятельных частей
переносятся в собственные модули; создавать несуществующие компоненты не нужно.

Общий Memory-index содержит краткую ссылку на Index объекта.
При повторной работе обновляются соответствующие файлы.
Старая монолитная заметка при следующей существенной работе разделяется,
а её прежний путь сохраняется как короткая навигационная заметка.

Запись каждой заметки выполняется условно: новая — CreateOnly,
существующая — IfMatchSha256 прочитанной версии. После записи проверяются
ok/exit code и SHA подготовленных байтов; затем файл читается обратно
с ExpectedSha256. Сначала проверяются модули, затем Index объекта,
последним общий Memory-index. При конфликте свежая версия объединяется
с новой правкой без потери обеих версий.

Secrets не копируются в обычные заметки и GitHub. В Index/модулях
допустимы только ссылки на соответствующие закрытые Secrets-заметки.
